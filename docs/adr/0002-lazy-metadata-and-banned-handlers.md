# ADR-0002 · 元数据只走属性页，禁止 `IPropertyStore` / 列 / 预览处理器

- 状态：**已采纳**（M0 冻结，禁止项）
- 日期：2026-11-03
- 相关：[design.md §P1/§P4/§7](../design.md)

## 上下文

"把包信息显示在资源管理器里"有五条路，成本差异极大：

| 路径 | 何时被调 | 典型代价 |
| --- | --- | --- |
| 属性页（`IShellPropSheetExt`） | 用户右键 → 属性 | 一生几次，可 1 s |
| 详细信息列 / 排序（`IPropertyStore`） | 每次浏览、每次排序、每次切列 | 每个文件 × 每次 |
| 悬停提示（Infotip） | 每次悬停 | 每个文件 × 每次悬停 |
| 预览窗格（`IPreviewHandler`） | 选中即调（Alt+P 常开时几乎是浏览级） | 每个文件 × 选中 |
| 自定义列（`IColumnHandler`） | 刷新/滚动 | 每行 |

ApkShellext2 选了 Infotip：鼠标划过一个目录就解析一遍 `AndroidManifest.xml` + `resources.arsc` `[上游]`。它的 issue #110 也证明"加属性页"是用户真实需求，只是没人做。

## 决策

1. **只注册 `IShellPropSheetExt`**（`HKCR\.<ext>\shellex\PropertySheetHandlers\<Name>`）。
2. **禁止**注册 `IPropertyStore`（属性处理器 `{8895B1C6-…}`）、列处理器、预览处理器、Infotip 扩展。
3. 属性页内**禁止**同步解析（见 [ADR-0003](0003-out-of-proc-parser.md) 与 design.md P4）：`AddPages` 只建空页。

## 后果

**正面**

- 这是"浏览零开销"（B2）唯一可靠的实现方式：系统没有机会在浏览路径上调用我们。
- 属性页可以慢慢解析、可以算 SHA-256、可以展示权限表，不必担心拖慢目录。

**负面**

- 系统"详细信息"标签页里看不到包名/版本（只有我们自己的标签页有）。若用户习惯在详情列里排序"版本号"，做不到。
- 需要用户多点一次（右键→属性），不像 Infotip 那样划过即见。这是刻意的取舍：**用一次点击换零开销**。

## 替代方案

| 方案 | 否决原因 |
| --- | --- |
| 只做 Infotip（ApkShellext2 路线） | 悬停即解析，目录一大就卡；且无法展示长字段 |
| 属性处理器（把字段塞进"详细信息"页） | 看起来更原生，但 Explorer 会为详情列/排序/提示批量调用，等于把解析挂到每次浏览 |
| 列处理器 | 同上，且要处理虚拟列、排序回调，复杂度最高 |
| 预览窗格 | `Alt+P` 常开时等于浏览级调用 |

## 修订条件

只有当"能按版本排序"被明确列为刚需时，才考虑加 `IPropertyStore`，并且必须先证明：它只被调用一次/文件（用 ProcMon 与 ETW 验证），否则不做。
