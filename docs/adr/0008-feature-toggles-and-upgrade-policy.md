# ADR-0008 · 安装包的功能开关、注册表归属与升级策略

- 状态：已采纳（2026-11-04）
- 关联：[architecture.md §2.4 / §4](../architecture.md)、[install.md](../install.md)、
  [verification.md R-0016](../verification.md)、ADR-0007（Inno Setup 按用户安装）

## 背景

用户提出两件事：

1. **装到一台已经装了同类工具的机器上时，不该硬抢。** 现有实现是"无条件覆盖"
   `.ext\DefaultIcon` 与 `.ext\ShellEx\{E357FCCD…}`，卸载时无条件删除——对"别人已经占了这两个位置"的
   机器，我们既覆盖了别人的设置，卸载后也**不会**把别人的设置还回去（值被删成空）。
2. **功能要能局部关掉。** 三层能力里，属性页是核心；缩略图与静态图标替换在"已经有别的工具干了这件事"
   的机器上反而是多余甚至有害的。

同时要把升级行为说清楚并做到位（实测：升级是就地追加卸载日志，但会把 `UiLanguage` 重置为 `auto`）。

## 决策

### 1. 两个功能各有一个开关，属性页恒开

| 功能 | 注册表表面 | 开关 |
| --- | --- | --- |
| 缩略图 | 5× `.ext\ShellEx\{E357FCCD-A995-4576-B01F-234630154E96}` | `thumb` |
| 静态图标 | 5× `.ext\DefaultIcon` | `icon` |
| 属性页 | 5× `.ext\shellex\PropertySheetHandlers\ApkInfo` | **无（核心功能）** |

COM 类注册（两个 `CLSID\…\InprocServer32`）**不设开关**：没有 handler 指向它时它是惰性的，
保留它才能让"关掉之后再打开"不必重装，也让卸载时的声明式回滚始终有东西可回滚。

开关有两个入口、语义一致：

- **安装期**：Inno `[Tasks]`（`thumb` / `icon`，默认都勾）。`UsePreviousTasks=yes` 默认开启，
  升级沿用上一次的选择。
- **装好之后**：`apkinfo.exe --features [thumb=on|off][,icon=on|off][,all=on|off]`，不带参数 = 查询。
  改完调 `SHChangeNotify(SHCNE_ASSOCCHANGED)`；`prop=off` 直接拒绝（退出码 4）。

### 2. 安装期探测"撞车"，按功能分别询问；默认保持原样

在 `CurStepChanged(ssInstall)`（文件与注册表还没动）读一遍目标机器：

- 缩略图撞车 = `.ext\ShellEx\{E357FCCD…}` 有值且不是我们的 CLSID **且**该 CLSID 的 `InprocServer32`
  指向一个真实存在的 DLL（死注册不算，覆盖它反而是清理）；
- 图标撞车 = `.ext\DefaultIcon` 有值且不是 `…\icons\<该扩展名>.ico` **且**文件存在。

有撞车就弹一个 `MsgBox`（每个功能一次），**默认按钮 = "否（保持原样）"**；
用户答"否"→ `Check: AllowThumb/AllowIcon` 返回 False → Inno **整套条目跳过**。

> 实测（R-0016）：被 `Check` 跳过的条目**不会进卸载日志，卸载时也不会被碰**。
> 所以"保持原样"= 别人的值从安装到卸载全程没人动，**不需要备份/还原机制**。

静默安装不能弹窗：默认与交互一致（保持原样），要接管必须显式
`/OVERWRITE=thumb` / `/OVERWRITE=icon` / `/OVERWRITE=all`。

### 3. 注册表写入用声明式，撤销多一道代码兜底

- `.ext` 表面上的 15 个值由 `[Registry]` 声明（带 `Tasks` + `Check`），卸载由 `uninsdeletevalue` 回滚。
- **`[UninstallRun]` 在删文件之前跑一次 `apkinfo --features all=off`**：覆盖"装的时候关了、后来用命令打开"
  的那些值——它们从没进过卸载日志，声明式回滚不认识它们。
- `--features` 删除时只删"指向我们自己"的值（缩略图比 CLSID；图标认 `\icons\<file>` 且文件存在，
  这样开发态 `out\x64` 与安装态都能认出来），删完把空壳键也删掉（等价 `uninsdeletekeyifempty`）。

### 4. 升级：就地追加卸载日志，不先卸载

`AppId` 不变 + `UsePreviousAppDir`（默认 yes）→ Inno **不会先卸载旧版**，而是把新版的记录**追加**到
同一份 `unins000.dat`；卸载时逆序回滚所有版本，应用列表里始终只有一条。

配套四条：

1. `UiLanguage` 加 `createvalueifdoesntexist`：否则每次升级都会把用户选的 `zh`/`en` 顶回 `auto`
   （实测过，见 R-0016）。
2. **`CloseApplications=force`**：取过一次缩略图后 `apkthumb.dll` 会被 COM Surrogate（`dllhost.exe`）
   占着，RestartManager 关不掉它 → 默认 `yes` 时静默升级会以"某些应用程序无法关闭"中止（实测退出码 5）。
   被强关的只有 explorer / dllhost 两个宿主进程，都不承载用户数据。
3. **不做**降级提示/拦截（用户 2026-11-04 明确不要：安装器保持无感）。
4. 版本号仍手写在 `.iss`（`AppVersion`）；与 `src/version.h` 的同源化留作待办，不进本次范围。

## 后果

**正面**

- 已经有同类工具的机器不会被无声接管；用户答"保持原样"时，别人的注册值全程没被碰过（有实测）。
- 三层能力可自由组合：只装属性页也是合法安装（`/TASKS=""`，实测通过 `verify-install -Features prop`）。
- 随时可改，不需要重装（`--features`）。
- 升级不再重置界面语言；`/VERYSILENT` 依然一条命令装完。

**负面 / 已接受的限制**

1. **"装好之后又被别的程序接管，再卸载我们"这种情形不管**（用户明确排除）：那种情况下
   `uninsdeletevalue` 会把别人的值删掉。要堵它只能把 15 个值的读/写/撤销全搬进代码
   （`--register/--unregister`），本次不做。
2. 用户选"覆盖"时，别人的设置确实丢失且不会还原——这是用户显式选择的语义，文档里写清楚。
3. 声明式回滚 + 代码兜底是**两套撤销路径**，实现时必须保证"代码只删自己的"（已有 `--features` 的
   所有权判断兜住），否则会出现"卸载把刚还原的值再删一次"。
4. 安装器界面仍是英文，而系统消息框（`MsgBox`）跟随系统语言：中文系统上会出现
   "英文正文 + 是/否按钮"的混排（见 `docs/evidence/feature-conflict-prompt.png`）。
5. 追加日志模式不会删除"新版已不再安装"的旧文件；将来砍文件会留孤儿（无害，卸载时删不到就跳过）。

## 替代方案与被否原因

- **安装前备份原值、卸载时还原**：能覆盖"覆盖后还原"，但代码量更大，且要处理"备份里指向的文件已经不存在"。
  用户选择"探测 + 询问 + 压根不写"，语义更简单（不写就没有还原问题）。
- **把 15 个值的读写全搬进 `apkinfo.exe`**：能堵上面第 1 条限制，代价约 200 行 + 卸载依赖 exe 存活
  （exe 被删则注册表成孤儿）。用户明确排除，保留为以后可加的一条。
- **加"禁止降级"提示**：用户不要（安装器保持无感）。
- **关掉某个功能时同时删 COM 类注册**：会让"关→开"退化到需要重装；惰性 CLSID 没有副作用，保留。

## 修订条件

- 用户遇到"我们关上之后别家接管、卸载误删"的实际案例 → 升级到"全部代码化"方案。
- 出现第三种功能（例如将来的 `IExtractIcon` 或列处理器）→ 先在这里加一行开关矩阵，再动代码。
- 版本号同源化（`.iss` 读 `src/version.h`）落地后，把本文 §4.3 改成"已同源"。
