# ADR-0001 · 缩略图只挂 `IThumbnailProvider`

- 状态：**已采纳**（M0 冻结；M5 可评估修订）
- 日期：2026-11-03
- 相关：[design.md §P1](../design.md)、[architecture.md §2.1](../architecture.md)

## 上下文

Explorer 有两个入口可以让 `.apk` 显示出包内图标：

1. `IThumbnailProvider`（`{E357FCCD-A995-4576-B01F-234630154E96}`）：只在**大图标/超大图标/内容视图**、且系统 thumbcache 未命中时调用；结果进 `thumbcache_*.db`。
2. `IExtractIcon`（`{BB2E617C-0920-11D1-9A0B-00C04FC2D6C1}`）：**每次绘制**都会调（列表/详细信息/滚动/刷新），Windows 不替我们缓存结果。

果核看图 3.4.16.125 的实测：唯一的壳扩展 `guohe-view-thumb.dll` 只实现 `IThumbnailProvider`，未实现 `IExtractIcon` `[实测]`。ApkShellext2 则同时提供图标与 Infotip，代价是每次悬停解析 `[上游]`。

## 决策

**v1 只注册 `IThumbnailProvider`**，不注册 `IExtractIcon`。

- 注册位置：`HKCR\.apk\ShellEx\{E357FCCD-…}`（按扩展名，不挂 `*`）。
- 小图标/列表/详细信息视图下，`.apk` 仍显示系统默认类型图标——**这是有意为之**。

## 后果

**正面**

- 浏览开销与未安装时相同（B2）：列表视图根本不会叫到我们。
- 缩略图请求频率低，允许 300 ms 预算，也允许在 DLL 内用 WIC 解码。
- 系统 thumbcache 帮我们做第二层缓存，二次进入目录几乎零成本。

**负面**

- 小图标视图看不到应用图标；用户若把目录当"图标墙"用（中等图标也想要），体验有落差。
- 需要向用户解释"为什么大图标有、小图标没有"。

## 替代方案

| 方案 | 否决原因 |
| --- | --- |
| 同时挂 `IExtractIcon` | 每次绘制一次调用，等于把"零开销"承诺作废；且结果需自建缓存（磁盘/内存），复杂度与风险都上一个台阶 |
| 只挂 `IExtractIcon`，不挂 thumb | 缩略图视图会走 icon 缩放，画质差；且频率高 |
| 挂 `IExtractIcon` 但只返回静态图标（不解析） | 没有意义，系统默认图标已够 |

## 修订段

### 2026-11-03 · 小图标策略确认

评审确认：**接受"小图标 / 列表 / 详细信息视图不显示包内图标"**，改用按扩展名区分的静态 ico（`DefaultIcon`，见 [architecture.md §2.4](../architecture.md)）。静态图标由 Explorer 直接读文件资源，**不进入任何代码路径**，因此与本 ADR 的"不挂 `IExtractIcon`"不冲突，V1 判据（0 次 `CreateFile`）不变。

同时明确：M5 之前小图标保持系统默认（白纸）；M5 交付 ico 资源（16/24/32/48/256 五档）与注册。若将来仍想要"小图标也显示包内图标"，按修订条件另开 ADR，不改本 ADR 的结论。

## 修订条件

M5 若实测"中等图标视图"是主要使用场景，可另立 ADR-0005：加挂 `IExtractIcon`，但必须满足——只读中央目录 ≤ 8 KB、结果落盘缓存、硬超时 100 ms、切换开关默认关闭。届时需重跑 V1（零开销判据改为"仅列表视图为 0"，且必须证明静态 ico 与包内图标可共存）。
