## 写作约定

1. **结论先行**：每节第一句是结论，论证放后面。
2. **断言可追溯**：技术断言标注 `[实测]`（本机二进制/注册表/工具输出）、`[上游]`（官方文档/issue/源码）。没有出处的写"待验证"，不写"据说"。
3. **决策与实现分离**：影响调用频率、进程边界、依赖边界的决定必须进 ADR；实现细节进 architecture。
4. **ADR 不可改写结论**：需要变更时新开 ADR（编号递增），旧 ADR 只在末尾追加"修订段"。
5. **验收必须有数字**：判据写成"≤ 300 ms / 0 次 / ≤ 3 MB"，并给出复现命令。
6. **文档与代码不一致时**：以能跑的证据为准，改文档；若代码确实偏离设计，补 ADR 说明原因。
